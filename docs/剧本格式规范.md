# 分镜剧本外层格式规范（生成剧本请照此模板）

> 适用对象：生成「逐镜执行剧本」的一方（人或 LLM 工作流）。
> 本文档**只规定镜外骨架**——镜头标题、时长声明、素材绑定表、编号规则。
> 每镜内部的提示词正文遵循 **MiniMax H3 标准结构**，本规范不另做限定，
> 只列出系统确定性依赖的三个锚点（见 §6）。
>
> 只要外层骨架符合本规范，系统走零 LLM 的确定性路径：成稿直录 + 素材按表绑定，
> 不经过模型猜测，不会错绑、漏绑。

---

## 1. 全片结构

```
（全局头部：本集说明、关键帧交付说明等，自由撰写，系统不解析）
# 镜头01｜标题
（本镜外层声明 + H3 成稿正文，见下）
# 镜头02｜标题
……
```

一镜一章，**不得**把多镜写进同一章。章与章之间的全局章节（如"稿尾说明"）不会
被并入任何一镜。

## 2. 镜头标题行（必须，决定切分）

推荐统一用：

```
# 镜头01｜黄金前三秒：颜色竟然在参与保护
```

规则：
- 行首 `#`～`####` 均可，编号词用 `镜头`/`分镜`/`片段`，编号为阿拉伯数字。
- 标题跟在 `｜` 或 `：` 之后，**至少含 2 个连续汉字**，不得是纯时长（如"7s"）。
- 也可用 `【第1镜】标题` 括号式，但推荐上面的 `镜头01｜标题` 式。
- 一镜一号，不得重号；同号两章会被去重闸门合并出错。

## 3. 镜长声明（每镜一条，推荐）

```
生成时长：6秒
```

（`Duration: 6s` / `Duration：6秒` 同样接受。）声明值是下限：若绑定配音总时长
装不下，系统会自动加长该镜并同步缩放正文时间引用。缺省时按 5 秒处理。

## 4. 素材绑定表（核心，每镜一张）

绑定表声明"本镜第 k 个参考槽位 ↔ 素材池第 N 个素材"。推荐唯一格式：

```
| 上传次序 | 本镜槽位 | 全局素材 | 用途 |
|---|---|---|---|
| 1 | Picture 1 | Image05.png | 首帧：小墨手持颗粒簇近景 |
| 2 | Picture 2 | Image06.png | 末态：小墨在左、观察细胞在右 |
| 3 | Audio 1 | Audio01.mp3 | 小墨原配音，完整复用 |
```

规则：
- **槽位列**：单元格恰好是 `Picture k`（图）或 `Audio k`（配音），k 从 1 连续编号。
  带尖括号 `<Picture 1>`、反引号包裹均可，裸写最简。
- **全局素材列**：图片写 `ImageNN.png`，配音写 `AudioNN.mp3`（或 `全局Audio NN`），
  视频写 `VideoNN.mp4`。N 就是素材池里的全局编号。
- **全局编号 = 上传顺序**：第 N 个上传的图片就是 `Image N`，第 N 段上传的音频就是
  `Audio N`。生成剧本时按交付包内文件号写，投递素材时**按同样顺序上传**。
- 用途列自由撰写（可标注"首帧/末态"等，供人核对）。
- 表中未列出的素材就是本镜不用，系统绝不偷偷补绑。
- 表行是唯一可信的声明位置：**散文里提到的 Image/Audio 编号一律不采信**。

首帧锚定（可选）：若需明确声明构图首帧，在表外加一行：

```
首帧：Image 05。
```

## 5. 台词（配音镜）

台词原文放在 H3 正文的 `Audio Timeline` 小节（英文标准式），或投搞式中文声明行：

```
Audio Timeline：0.40–4.99秒｜"等等……它们在帮细胞挡光？"
```

系统会确定性转成 H3 的 Audio Timeline 小节，台词引号内容逐字保留。
**不要**用 `<d>` 标签写台词（会诱导模型合成第二路语音与参考音频叠放）。

## 6. 镜内正文：遵循 H3 标准

每镜正文是一个 ```text 围栏的 H3 提示词，按 H3 标准结构撰写
（subject_definitions / detailed_description / summary / retention_analysis /
cinematography 等工艺段）。系统确定性依赖的锚点只有三个：

1. 围栏正文以行首 `subject_definitions:` 开始，且包含行首 `detailed_description:`
   段（成稿直录的判定依据；缺任一者会退回 LLM 规划路径，成稿可能被改写）；
2. 槽位标签用本镜号：`<Picture 1>`、`<Picture 2>`…、`<Audio 1>`，编号与绑定表
   槽位列严格一致，正文不得出现全局号标签（`<Image 5>`、`<Audio 3>`）；
3. 全局素材文件名如需在正文提及（如 "from Image05.png"），写成文件名，
   不加尖括号。

其余（六段工艺块、Shot 切分、风格约束等）按 H3 标准自由撰写。

## 7. 一镜完整示例（模板）

```
# 镜头01｜黄金前三秒：颜色竟然在参与保护

生成时长：6秒。

| 上传次序 | 本镜槽位 | 本文件夹内文件 | 用途 |
|---|---|---|---|
| 1 | Picture 1 | Image05.png | 首帧：小墨手持颗粒簇近景 |
| 2 | Picture 2 | Image06.png | 末态：小墨在左、观察细胞在右，闭口疑惑 |
| 3 | Audio 1 | Audio01.mp3 | 小墨原配音，完整复用 |

首帧：Image 05。

```text
subject_definitions:
<Subject 1> is …（按 H3 标准）
<Picture 1> is the opening frame …（本镜槽位号，与表一致）
<Picture 2> is …

detailed_description:
[Shot 1] …（按 H3 标准）

retention_analysis:
…（按 H3 标准）
```
```

## 8. 兼容格式（仍被支持，不推荐新稿使用）

以下旧稿式的声明区同样可解析，保留用于历史项目：

- `**Reference 图片上传绑定：**` 标题 + `- Picture 1 = Image 04（身份）` 清单行；
- 投稿式 `` **Reference 图片：** `<Picture 1>` ← Image 21 `` 内联声明；
- 连续编号 v3 清单 `- 第1张：`；
- V2 表头 `| 类型 | 本镜绑定 | 全局素材 | 用途/时点 |` + `` `<Picture 1>` `` +
  `全局Audio 01`。

新稿请一律用 §4 的推荐表式——它同时驱动绑定、成稿直录与时长解析。

## 9. 禁止事项（踩过的事故）

| 禁止 | 后果 |
|---|---|
| 散文里提 Image/Audio 编号当绑定 | 不被采信，素材悬空 |
| 本镜槽位号与全局号混写（正文 `<Audio 3>` 指全局第 3 段） | 组装闸门拦截，或错绑 |
| 重号/缺号的镜头标题 | 切分错乱，镜数校验失败中止 |
| `<d>` 台词标签 | 双音轨叠放事故 |
| 正文缺 `detailed_description:` 段 | 退回 LLM 路径，成稿被改写 |
| 引用未上传的素材编号 | 该槽位留空待补，不会自动找替代 |

## 10. 自检方式

投递后查看运行记录（项目页 → 运行记录 → bind 阶段）：

- `bind_reference_aligned`：逐镜列出对齐到的全局图号——应与绑定表完全一致；
- `bind_unused_by_script`：列出的应恰好是"本集未引用"的素材；
- 若出现 `bind_audio_align_crosscheck_failed` 或全镜图片为空，说明稿式不符合
  本规范，按 §4 修正后重投。

离线回归：`backend/tests/storyboard_v2_table_selfcheck.py`（29 项）覆盖本规范全部
解析路径，改解析器必须先过它。
